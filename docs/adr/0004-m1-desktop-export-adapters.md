# ADR 0004：M1 只读桌面、导出边界与适配器

- 状态：已接受（2026-11-05，进入 M1 / T07—T09）
- 前置：[ADR 0003](0003-m0-r2-evidence-admission-and-scope.md)；设计包 01/02/04/07/08/11
- 范围：WPF 只读桌面、脱敏导出、客户端适配与依赖解释；**不包含**任何网络写入口、修复执行或提权

## 决策

1. **WPF + WinForms 托盘，同进程。** `NetScope.Desktop` 为 `net10.0-windows`、`UseWPF`，并启用 `UseWindowsForms` 只为 `NotifyIcon`；不引入第三方 UI/NuGet。托盘与窗口共享同一观察会话，关闭窗口默认隐藏到托盘，显式退出才停止采集并 flush。
2. **轻量 MVVM，无框架。** 视图模型实现 `INotifyPropertyChanged`，命令用自写 `RelayCommand`；所有 UI 文本中文，结构化字段保留稳定英文标识。UI 线程只消费不可变结果，采集/探测在后台执行并可取消。
3. **只读边界进入编译期结构。** Desktop 不引用任何修复协调器；界面上没有“执行修复”入口，`AllowedRepairActions` 一律显示为“M1 不执行”。外部探测只能由用户显式点击并对已配置目标发起，且目标必须是用户填写的 http(s) 端点；观察会话默认只做本机快照，不自动联网。
4. **共享契约先行。** Application 层新增 `Adapters.cs`（客户端状态/证据来源/依赖解释）与 `Exports.cs`（预览、文件清单、脱敏摘要、导出结果）。Storage 实现导出；新 `NetScope.Adapters` 实现客户端适配；Desktop 只依赖这些抽象。
5. **导出默认最小化。** 沿用 04 §5—§6：导出包内使用随机 salt 生成稳定别名（用户/设备/内网地址/目录），salt 不随包输出；公网目标默认 target-A；包内保留事件关联与分类字段。D3（密钥、订阅、Cookie、聊天正文）不采集也不导出。预览只展示字段类别和计数，不展示原值。
6. **导入按不可信输入处理。** T08 提供包边界检查（总大小、文件数、单文件、嵌套深度、绝对路径/盘符/越界/符号链接拒绝），M1 不提供导入执行入口，只做拒绝测试与说明。
7. **适配器先通用后专用。** generic 适配器只读进程身份、监听端点、代理层与受支持的配置来源；Nice/Apex 专用适配器仅按字段白名单解析已确认配置，未知字段不猜；每条配置证据标 `runtime_api / process_start_reference / disk_only / user_report`，并记录 parser 版本、mtime、hash、有效性与读取时间。读不到即 unknown + reason。
8. **DSH/Antigravity 只解释依赖，不代为配置。** 依赖解释列出进程层、用户/机器环境、WinINET/WinHTTP、启动参数与目标域名，明确“哪一层可被该进程读取”与“未知继承”。不修改环境变量、不重启应用、不请求付费接口。
9. **本地数据位置。** 会话与设置位于 `%LOCALAPPDATA%\NetScopeRepair\`（Known Folder 推导，不硬编码用户名）；导出包写到用户选择的新目录，不覆盖已有包。M1 不设配额轮转（M2 T11）。
10. **验证方式。** 视图模型与导出/适配器用 xunit 无窗口验证；另提供 `NetScope.Desktop --render-screens <dir>` 离屏渲染各页面 PNG，用于人工与视觉核对。截图只证明展示，不替代行为测试。

## 代价与后续

- 观察会话在 M1 只覆盖手动启动期间；故障前后窗、自动触发、配额与崩溃恢复属 M2（T10/T11）。
- 真实探测仍可能受系统默认栈/TUN 影响，UI 只能展示路径与未知，不宣称物理直连。
- 导出匿名化为包内稳定别名，不是数学匿名；用户清楚知道包内保留了哪些类别。
- 客户端配置解析随客户端版本可能失效，适配器版本与有效性会显式展示，失败时降级为 unknown。
