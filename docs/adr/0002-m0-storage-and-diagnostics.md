# ADR 0002：M0 的存储、诊断与平台边界

- 状态：已接受
- 日期：2026-11-04
- 关联任务：T02、T03、T04、T05、T06

## 背景

M0 需要在没有修复能力的前提下，交付"能记录、能解释、能回放"的只读增量。有三个决策会
长期影响后续阶段，必须在第一次实现时就固定下来，否则 M1 之后的界面、导出和规则迭代会建立在
错误的前提上。

## 决策

### 1. NDJSON 是事实源，SQLite 只是可重建投影

事件一旦写入 NDJSON 就是权威记录；`SqliteEventIndex` 只做查询与时间线加速，可随时
`Rebuild` 重建。两条写入路径不能各自宣称自己是唯一真实源，因此投影使用
`INSERT OR IGNORE` 保持 event_id 身份不变，重复插入不会覆盖原记录。

理由：断网现场最怕"索引写成功但日志没落盘"。把事实源锁定为单文件追加日志，索引损坏时
只需要重建，不会产生两套互相矛盾的真相。

### 2. 诊断规则是零依赖纯函数，M0 只发布 7 条

规则只接收 `EvidenceSet`，不引用 `Process`、`HttpClient`、`Broker` 或任何平台 API。
M0 发布 DX-001/002/005/006/008/010/011。

未发布的规则及原因：

| 规则 | 不发布原因 |
|---|---|
| DX-003 TUN 流量路径异常 | 需要运行态 TUN 身份与目标路由查询，M1 才具备 |
| DX-004 IgnoreDefaultRoutes 异常 | 结论直接指向系统写入，必须等 M3 门禁 |
| DX-007 双栈差异 | 需要分族探测能力，M0 传输不支持强制地址族 |
| DX-009 应用代理残留 | 需要应用级配置采集（M1 适配器） |
| DX-012 上游或业务异常 | 需要区分代理链可达与业务失败的真实 HTTP 语义，依赖真实探测 |

理由：一条规则一旦发布，界面就会把它当成可信结论展示。宁可少发布，也不发布会产生
"看起来像根因"的规则。

### 3. 每条结论必须引用 evidence_id，且不得产出修复动作

`DiagnosticRuleBase.Create` 在 `evidence_ids` 为空时直接抛异常；`AllowedRepairActions`
恒为空。规则抛异常时引擎产出 `insufficient` 级别的"规则执行失败"诊断，而不是中断整轮。

理由：这是产品的核心承诺。没有引用的结论和没有出口的修复能力，是两类最容易在后期
悄悄长出来的偏差。

### 4. DX-002 只把"落在 fake-IP 段内的路由"当作配置证据

初版实现把任何覆盖 `198.18.0.0/15` 的路由（包括 `0.0.0.0/0` 默认路由）都当作 fake-IP
配置证据，结果是每台机器都会命中该规则，等于什么都没说。现改为：只有前缀本身落在
`198.18.0.0/15` 之内（前缀长度 ≥ 15）才计为证据；默认路由不计。

理由：规则的价值来自区分度。一条在所有样本上都触发的规则，会训练用户忽略它。

### 5. 真实探测默认关闭，能力缺失如实返回

`IProbeTransport` 可注入；CLI 与测试默认使用 `HttpProbeTransport` 之外的合成传输。
真实传输在无法保证的维度上不假装生效：地址族强制返回 `unsupported`；M0 不跟随重定向，
因此 3xx 记为 `reachable_unexpected` 而不是"跟随成功"。

理由：把"没做"说成"做了"，是诊断工具最严重的失真。

### 6. 平台边界：只有采集与 CLI 绑定 Windows

`NetScope.Domain`、`Application`、`Probes`、`Storage`、`Diagnostics` 保持 `net10.0`；
`Collectors.Windows` 与 `Cli` 使用 `net10.0-windows`。核心契约与规则可在无 Windows 桌面
组件的环境编译与测试。

## 后果

- 正面：索引可以随时丢弃重建；规则可用合成证据穷举测试；平台相关代码集中在两个项目。
- 负面：每次查询都要经过索引，索引缺失时需要一次全量重建；规则集合偏小，M1 前无法给出
  TUN 相关的结论。
- 缓解：G0 报告列出 M1 需要补齐的采集与规则，并按依赖顺序排列。

## 再评估条件

- 如果 SQLite 投影出现"日志与索引长期不一致"，重新评估是否改用 WAL 单写路径。
- 如果真实探测需要支持地址族与逐跳重定向，重新评估传输接口而非在实现里加开关。
- 如果 Windows IP Helper 的行结构在目标系统上变化，改为按 ABI 探测结构尺寸或改用
  `GetIpForwardTable` 系列中更稳定的入口。
