## 3. 独立复核与发现闭环

## 4. 用户日用机只读试用方案

1. `dotnet build NetScopeRepair.slnx`，运行 `src/NetScope.Desktop/bin/Debug/net10.0-windows/NetScope.Desktop.exe`（或 `dotnet run --project src/NetScope.Desktop`）。
2. 保持默认观察；需要时在“设置”填写一个 **http(s)** 探测目标与期望状态码，保存后点“立即诊断”。不要求填写代理端点；不填时显式路径会如实报告未配置。
3. 正常使用 DSH、Antigravity、Chrome 与 TUN 场景；关闭窗口隐藏到托盘继续观察，观察至少一个工作日。
4. 出问题时刻：在“时间线”点“重新读取时间线”，查看事件、读取问题与序号缺口；在“诊断与证据”查看结论、反证、缺失证据与作用域。
5. 结束时右键托盘“退出”（或在关闭询问中选择退出），确认日志 flush；用“导出”先预览再生成 ZIP。
6. 试用记录：故障是否发生、界面解释是否看得懂、状态是否诚实、导出是否包含不该有的隐私、退出后是否停止记录。记录结果再决定是否进入 G2/M2。

**试用边界**：隐藏期间只保留当前观察；退出期间不承诺故障前窗（M2 才实现）；托盘与关闭交互本轮未自动化实测，试用时请特别核对隐藏后采集是否继续、退出后是否停止。

## 5. 残余限界

- 真实 IPv4/IPv6 强制、真实外部握手/认证、浏览器实际代理链未验收；`no-explicit-proxy` 不证明物理直连。
- 适配器真实 Nice/Apex 进程名、配置结构与 `GetExtendedTcpTable` 行为未真机验证；所有测试用合成 fixture。
- 托盘交互、系统托盘提示、真实隐藏/恢复未自动化；仅离屏渲染与启动冒烟。托盘未显示“写入受限”状态。
- 导出无保留公网域选项、无包大小上限；预览与导出之间日志变化可能改变结果；自由文本 D3 依赖上游不采集。
- 观察间隔修改在下次开始观察后生效；导出预览会在下一采集周期被重置；时间线需手动重新读取（界面不自动刷新）。
- M1 无配额/轮转/崩溃恢复/多快照工作台；这些属于 M2 T10—T12。
- 未启动 M2、未实现修复执行、未申请管理员权限、未上传任何日志。
