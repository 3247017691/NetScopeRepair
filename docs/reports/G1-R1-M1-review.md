## 4. 原 TUN 修复脚本功能对账

本次只读检查的桌面批处理入口（`%USERPROFILE%/Desktop/修复TUN优先级.bat`）共 4 行，只调用旁边的 PowerShell v2 脚本（`%USERPROFILE%/Desktop/fix-tun-priority.ps1`），该脚本现为 387 行。原设计审计描述的是更早的 218 行版本，不能代替本次对最新文件的核对。

| 原脚本能力 | 当前软件 |
|---|---|
| 查网卡、路由、接口度量、自动度量和 IgnoreDefaultRoutes | 有只读采集；数据读取不完整时保留缺口 |
| DNS/代理与无显式代理探测 | 有探测底座；必须配置目标并显式启动。未验证真实外部链路 |
| 自动提权后设 TUN metric=1、关闭自动度量 | **未实现**；M3 的受控动作目标，当前无执行入口 |
| IgnoreDefaultRoutes=Enabled 时关闭它 | **未实现**；M3 动作目标 |
| 修改后验证与恢复 | **未实现**事务与撤销；不能把当前程序当修复器 |
| 原文件与原入口 | 保留原状，未调用、删除、替换或包装成软件按钮 |

TUN 优先级修复仍属于用户已确认的首版核心需求，而不是从产品目标中删除。原施工计划明确：M0—M2 是诊断增量，完整自用首版至少覆盖 M3；T13—T16 才实现平台动作、broker、事务、预览与恢复 UI。

不能通过在 GUI 中直接调用旧脚本来补齐：现脚本仍按候选列表取第一个 TUN，写入前没有逐动作计划，且回退分支只恢复度量相关值，没有保存和恢复原 IgnoreDefaultRoutes。新程序需要用已确认接口身份、实际 before/after、写前记录、读回及冲突处理迁移这项能力；读取接口参数不等于具备写入能力。

## 5. 试用范围与剩余限制

- 当前可试：本地状态记录、手动诊断、时间线、证据解释、多客户端只读信息与本地脱敏导出。**不可试：TUN 修复或撤销。**
- 日常一整天试用、托盘鼠标隐藏/恢复/退出、真实外部连通性、业务应用恢复未执行，不能写成已验收。只读生命周期与显示页面已有源码、单测和冒烟证据。
- 真实 Nice 仅验证本次安装版本的白名单读取；来源仍为 `disk_only`，不证明进程加载了该文件。Apex 当前无有效实机配置证据，运行 API/启动引用没有默认真实接入。
- 地址别名是占位，IPv4 可能碰撞，任意前缀/公网拓扑不保证；导出包可检查记录、引用与已验证类别，不能用它认定原始路由拓扑等价或授权修复。详细限制随包附带。
- 自由文本的任意片段化身份、无结构公网 host:port 不保证识别；身份 ID/时间有意保留。当前禁止采集凭据和配置全文，分享前仍需查看预览；有限标记扫描不是对所有可能敏感值的证明。
- M1 无配额/轮转/故障前后窗/崩溃恢复，观察间隔下次开始生效，时间线手动刷新。ZIP 准入没有产品导入入口；未来启用前须补输入流与内容验证，当前不宣称完整导入安全。
